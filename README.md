# CacheSimulatorVerilog

Модель процессорного кэша на SystemVerilog для сравнения политик вытеснения **LRU** и **bit-pLRU**. Проект моделирует обмен между процессором, кэшем и контроллером памяти по тактам и собирает статистику попаданий при обращениях к массивам в алгоритме умножения матриц.

Разработан в рамках курса архитектуры компьютера в ИТМО. Основные части реализации — конечные автоматы управления, двунаправленные шины, обработка попаданий и промахов, выбор вытесняемой строки и обратная запись изменённых данных.

## Возможности

- Четырёхканальный наборно-ассоциативный кэш с отдельными признаками `valid` и `dirty` для каждой строки.
- Две политики вытеснения в одном модуле: LRU на основе счётчиков возраста и bit-pLRU на основе битов обращения.
- Чтение и запись данных размером 8, 16 и 32 бита.
- Схема **write-back**: изменённая строка отправляется контроллеру памяти при вытеснении.
- Схема **write-allocate**: промах при записи вызывает загрузку строки в кэш.
- Передача данных по 16-битным шинам в порядке little-endian.
- Сброс состояния через `reset`, счётчики попаданий `hits` и обращений `accesses`.

Политика выбирается параметром `IS_PLRU`: значение `0` включает LRU, значение `1` — bit-pLRU. Тестовый модуль создаёт два экземпляра кэша с отдельными контроллерами памяти и подаёт им одинаковую последовательность запросов.

## Конфигурация

Параметры системы заданы в `constants.sv`.

| Параметр | Значение |
| --- | --- |
| Адресное пространство | 512 КиБ, адрес 19 бит |
| Объём данных кэша | 2 КиБ |
| Размер строки | 32 байта |
| Количество строк | 64 |
| Количество наборов | 16 |
| Ассоциативность | 4 |
| Разбиение адреса | tag: 10 бит, index: 4 бита, offset: 5 бит |
| Шины данных `D1`, `D2` | 16 бит |
| Шины адреса `A1`, `A2` | 14 бит |

Адрес от процессора передаётся за два такта: сначала tag и index, затем offset. Между кэшем и контроллером памяти передаётся адрес строки без offset, а данные пересылаются целой строкой.

## Структура проекта

| Файл | Назначение |
| --- | --- |
| `cache.sv` | Модуль кэша: хранение строк, обработка запросов, вытеснение и статистика |
| `memctr.sv` | Модель контроллера памяти с обработкой чтения и записи строк |
| `constants.sv` | Размеры кэша и шин, коды команд и состояния контроллера |
| `tb.sv` | Генератор тактов и запросов, запуск двух конфигураций и вывод статистики |

## Запуск

Для симуляции нужен **Icarus Verilog 12.0 или новее**, включая утилиты `iverilog` и `vvp`. Выполните команды из корня репозитория:

```sh
iverilog -g2012 -o tb.out tb.sv
vvp tb.out
```

Флаг `-g2012` включает поддержку SystemVerilog. Остальные исходники подключаются из `tb.sv` через директивы `include`.

## Тестовый сценарий

Тестбенч воспроизводит обращения к памяти при умножении матриц `a[64][32]` и `b[32][60]` с записью результата в `c[64][60]`. Элементы массивов занимают 1, 2 и 4 байта соответственно. Массивы расположены последовательно, начиная с адреса `0x128`.

Внутренний цикл читает элемент `a` и элемент `b`, после чего для каждого элемента результата выполняется 32-битная запись. Для каждой политики формируется 249 600 запросов. После завершения симуляции выводится таблица с количеством попаданий, общим числом обращений и процентом попаданий для LRU и bpLRU.

## Границы модели

Проект предназначен для исследования поведения кэша на последовательности адресов. Тестбенч воспроизводит доступы алгоритма, а при записи результата передаёт нулевое значение. Контроллер `memctr.sv` возвращает нулевые строки при чтении и не хранит полноценный массив оперативной памяти, поэтому сценарий не проверяет численный результат умножения матриц.

Запросы предполагаются в пределах одной кэш-строки. Изменение конфигурации требует проверки зависимых разрядностей и логики модулей.
